# 온보딩 결정 이력

## NTRP 선택지 확정

사용자가 온보딩의 NTRP 선택지를 1.0부터 3.5까지 0.5 간격과 최상위 4.0+로 정정했다. 이슈 #14와 인증 도메인 결정을 갱신했다.

## 온보딩 입력과 프로필 이미지 정정

사용자가 입상 이력 삭제, 활동 지역 최대 3개, 단식·랠리·복식·혼합복식 복수 선택, 동성만과 혼합복식 동시 선택 금지, 프로필 이미지 설정 지원을 요청했다. 프로필 이미지는 선택 설정으로 기록하고 소셜 이미지 기본 후보의 제공 조건과 업로드 계약은 후속 검토로 남겼다.

## 프로필 사진 초기 저장소

사용자가 직접 업로드하는 프로필 사진을 초기에는 EC2의 Docker 볼륨에 저장하기로 결정했다. 이슈 #14와 인증 도메인 결정에 반영했다.


## 상세 설계 첫 라운드 확정

사용자가 Q1~Q5의 추천안을 승인했다. 기존 회원 모델 재사용, 구력 네 구간, NTRP 상위 구간 표현, 복식 선호의 범위, 프로필 사진 즉시 적용을 확정했다. 요청 형식은 [온보딩 API 합의](api.md#온보딩-완료-요청)에 정리했다.

## 온보딩 환영 인사와 닉네임 추천

사용자가 추천 닉네임은 랠릿에서 생성하고, 구글과 카카오가 제공한 이름은 온보딩 초기 화면의 환영 인사에만 사용할 수 있게 API로 제공하기로 결정했다.

## 내 정보 응답과 프로필 사진 계약

사용자가 내 정보와 온보딩 완료의 동일한 응답, JPG·JPEG·PNG 파일당 최대 5MB와 프론트·백엔드 검증, 모든 회원에게 프로필 사진 조회 허용을 승인했다. 소셜 이름은 앞서 확정한 환영 인사 용도를 적용한다.

## Q8 활동 지역 모델과 코드 확정

플랩풋볼 원본 API에서 서울 그룹 ID `1`과 마포구 지역 ID `139`를 확인했다. 랠릿은 시·도와 자치구의 관계를 참고하고, 공식 코드를 초기 시드부터 저장하기로 했다. 사용자가 자치구까지만 두는 범위에 동의했다. [API 합의](api.md#활동-지역)에 반영했다.

## Q11 프로필 사진 조회 인증 확정

사용자가 로그인한 회원 모두에게 기존 Bearer 액세스 토큰으로 프로필 사진 조회를 허용하기로 결정했다. [API 합의](api.md#프로필-사진)에 요청 방식을 기록했다.

## Q12 프로필 기본 이미지 확정

사용자가 구글·카카오 프로필 사진은 이번 온보딩에서 받지 않고, 사진을 직접 지정하지 않은 회원에게 랠릿 기본 이미지를 표시하기로 결정했다. [API 합의](api.md#내-정보와-온보딩-완료-응답)에 반영했다.

## Q13 활동 지역 조회 API 확정

사용자가 추후 지원 시·도를 추가할 때 시·도 선택과 자치구 조회를 각각 처리할 수 있도록 두 목록을 별도 API로 제공하기로 결정했다. [API 합의](api.md#활동-지역)에 경로를 기록했다.

## Q14 기존 온보딩 컬럼 정리 확정

사용자가 배포 DB의 대상 컬럼에 저장된 값이 없다고 확인하고 정리를 승인했다. 새 Flyway 마이그레이션에서 `users.activity_latitude`, `users.activity_longitude`, `users.activity_radius_km`, `users.tournament_history`를 제거하고 회원 엔티티의 관련 필드와 완료 로직도 정리한다. 기존 적용 마이그레이션은 유지한다.

## Q15 프로필 사진 삭제와 저장 키 확정

사용자가 기본 이미지로 되돌리는 API와 추후 S3 교체를 고려한 저장 키 방식을 승인했다. 저장소가 바뀌어도 랠릿 조회 URL과 Bearer 인증을 유지하는 방향이다. 초기 사진을 보존할 필요가 없으면 S3 전환 때 기존 사진 키를 비우고 기본 이미지로 되돌릴 수 있다. [API 합의](api.md#프로필-사진)

## Q16 소셜 표시 이름 보관 정책 확정

사용자가 가입 완료 시 소셜 표시 이름을 보관하기로 결정했다. 응답 범위는 [API 합의](api.md#내-정보와-온보딩-완료-응답)에 반영했다.

후속 논의에서 본인 회원 응답은 가입 상태와 관계없이 소셜 표시 이름을 반환하는 것으로 조정했다. 상태에 따라 응답을 분기하지 않고, 프론트에서 온보딩 환영 인사에 사용한다.

## Q17 기존 컬럼 제거 시점 확정

사용자는 실사용자가 없는 임시 운영 상태를 고려해 기존 컬럼을 #14의 새 Flyway 마이그레이션에서 제거하는 쪽을 승인했다. 이전 이미지가 같은 DB에서 스키마 검증에 실패할 수 있다는 배포 복구 제약을 확인했다.

2026-11-13 사용자는 배포 DB에 보존할 데이터가 없음을 다시 확인했다. 이 조건에서 데이터 백업과 복원 검증을 배포의 선행 조건으로 잡았던 제안을 철회했다.

## 구현 중 검증 보강

잘린 파일이 이미지 헤더 검사를 통과하는 상황을 재현했다. 디코딩 검증을 추가하고 서버 자원 사용을 제한하기 위해 픽셀 상한을 둔다. 파일 교체 중 이전 파일이 사라졌다면 최신 DB 키를 한 번 다시 조회한다. 온보딩은 숫자가 열거형, 불리언, 문자열로 자동 변환되는 입력을 거절한다.

## 프로필 사진 개인정보와 온보딩 저장 충돌 리뷰

사용자가 프로필 사진의 EXIF 방향 적용과 촬영 메타데이터 제거, 실제 DB 닉네임 충돌의 롤백 검증을 승인했다. 저장소에 전달하기 전에 이미지 바이트를 재인코딩하고 긴 변의 상한을 1,024px로 정했다. 기존 테스트 사진은 새로 업로드하면 처리되며, S3 전환 시 보존이 필요 없는 사진은 기존 결정에 따라 기본 이미지로 되돌릴 수 있다.

## 사진 저장과 온보딩 검증 후속 리뷰

2026-11-13 사용자가 사진 변환·저장과 회원 트랜잭션을 분리하고, 사진 저장소가 키 누락을 공통 계약으로 표현하며, 온보딩 도메인 위반 사유를 기존 API 오류로 변환하도록 승인했다. V6·V9 컬럼 정리는 배포 DB에 보존할 데이터가 없다는 전제에서 #14 범위로 유지한다.

## 온보딩 완료 HTTP 메서드 변경

사용자가 가입 완료 동작을 `POST /api/v1/users/me/onboarding`으로 변경하도록 승인했다. 동일 내용 재시도는 `200`, 완료 후 다른 내용은 `409`를 유지한다. 마이페이지 프로필 수정은 후속 작업이다.

## 기본 닉네임 생성 형식 변경

사용자가 최초 소셜 로그인에서 생성하는 기본 닉네임을 형용사, 테니스 용어, 숫자 세 자리 조합으로 변경하도록 승인했다. 기존 대소문자 무시 유일성 제약과 최대 다섯 번 저장 시도를 유지한다.

## 온보딩 Swagger 설명 보강

사용자가 사진 삭제의 `204`, 온보딩 요청 예시와 오류 응답, 내 정보 필드의 의미, 지역·닉네임 조회 사용법을 Swagger에 반영하도록 승인했다. 설명은 짧은 한글 문장으로 두고, 온보딩 완료에는 요청 예시 한 개를 제공한다.
